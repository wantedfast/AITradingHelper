# WANG Agent Audit

## Scope

This audit covers the current WANG Industry Agent path before YingHang V3 refactor.

Primary code paths:

- `trade_review_agent/workbench_context.py`
- `trade_review_agent/workbench_news.py`
- `trade_review_agent/workbench_agents.py`
- `trade_review_agent/workbench_composer.py`
- `trade_review_agent/workbench_schema.py`
- `trade_review_agent/presenter_agent.py`

## Current Role

WANG currently acts as an LLM-based industry-chain structurer. It is asked to infer:

- industry rating
- sector/theme
- current market hype
- traded business line
- profit flow
- moat radar
- logic tree
- sector symbol
- peer ranking

It is not a pure data engine. Most conclusions are LLM inference over a compact context.

## Input Lineage

```text
TradeRound + local analysis + stock/sector/benchmark frames
  -> build_stock_context()
  -> Market Catalyst context
  -> WANG prompt
  -> OpenAI JSON
  -> _research_agent_payload()
  -> compose_workbench_data()
  -> merge_default_workbench()
  -> presenter fallback / frontend
```

## How Conclusions Are Reached

WANG reaches conclusions by asking the LLM to map the compact `stock_context` into a required JSON contract. There is no deterministic scoring layer for `industry_rating`, `moat_radar`, `profit_flow`, `logic_tree`, or `peer_ranking`.

The only real numeric inputs are:

- buy-day stock/sector/benchmark pct
- recent 20 trading-day close return summaries
- trade return/score from local analysis

There is no real numeric input for:

- revenue growth
- profit growth
- gross margin
- valuation
- PE/PB
- segment revenue
- order backlog
- peer fundamentals
- peer valuation

Therefore, industry conclusions are best classified as LLM narrative inference, not evidence-complete research.

## Fallback and Template Pollution

WANG raw output is preserved in `workbench.wang_agent`, but final user-facing fields pass through composer, schema normalizer, and presenter fallback.

Important fallback effects:

- `hero.industry_rating` becomes `B` if missing.
- `profit_flow` fields become `pending verification` if missing.
- Presenter can generate default `profit_flow.items`.
- Presenter can generate default `logic_tree`.
- Presenter can derive tags from keywords such as light communication, new energy, pledge, earnings.
- `weakest_link` and `peer_ranking` can be generated by WANG but not meaningfully surfaced.

## Coverage Concerns

WANG prompt is generic enough for many industries, but upstream Market Catalyst queries include industry-specific hints: capacitor, AI, robot, new energy. That biases market-theme discovery.

No structured sector taxonomy exists. No verified industry map exists. `sector_symbol` is model-guessed unless other hardcoded hints override it elsewhere.

## V3 Implication

For V3, WANG should not be allowed to produce final user answers. It should become a research layer only:

```json
{
  "research_layers": {
    "wang_industry": {}
  },
  "source_trace": {
    "wang_industry.profit_flow": "llm",
    "wang_industry.moat_radar": "llm",
    "wang_industry.peer_ranking": "llm_or_missing"
  }
}
```

If real data is missing, the field should say `missing` or `pending verification`, not receive default scores or pseudo-percentages.
