# Public Equity Agent Audit

## Scope

This audit covers the current Public Equity Agent path before YingHang V3 refactor.

Primary code paths:

- `trade_review_agent/workbench_context.py`
- `trade_review_agent/workbench_agents.py`
- `trade_review_agent/workbench_composer.py`
- `trade_review_agent/workbench_schema.py`
- `trade_review_agent/presenter_agent.py`

## Current Role

Public Equity currently acts as an LLM-based company-quality and investment-judgment structurer. It is asked to infer:

- investment rating
- one-sentence conclusion
- market expectation gap
- validation panel
- catalysts
- risks
- action
- financial validation
- valuation odds
- position sizing
- trading implication

It does not currently receive real financial statements, valuation tables, consensus expectations, or peer fundamentals.

## Input Lineage

```text
TradeRound + local analysis + market snapshots + Market Catalyst
  -> build_stock_context()
  -> Public Equity prompt
  -> OpenAI JSON
  -> _research_agent_payload()
  -> compose_workbench_data()
  -> merge_default_workbench()
  -> presenter fallback / frontend
```

| Input field | Source | Actual data quality |
|---|---|---|
| `company` | trade/resolver | real_data |
| `trade` | `TradeRound` + local analysis | real_data |
| `market` | stock/sector/benchmark summaries | real_data but compressed |
| `financials.revenue_growth` | hardcoded `pending fetch` | missing |
| `financials.profit_growth` | hardcoded `pending fetch` | missing |
| `financials.gross_margin` | hardcoded `pending fetch` | missing |

There is a helper named `_context_with_wang_pre_read`, but current execution runs WANG and Public Equity in parallel with the same original context. Public Equity does not actually consume WANG's pre-read in the current flow.

## How Conclusions Are Reached

The Public Equity Agent reaches conclusions by asking the LLM to infer a complete investment judgment from:

- trade outcome
- buy/sell verdicts from local analysis
- compressed market performance
- current-market catalyst summary
- missing financial placeholders

It does not calculate:

- actual earnings quality
- historical revenue/profit growth
- margin trend
- valuation percentile
- consensus expectation gap
- peer valuation comparison
- balance sheet risk

Therefore, `investment_rating`, `expectation_gap`, `financial_validation`, and `valuation_odds` are not data-complete investment conclusions. They are LLM hypotheses.

## Fallback and Template Pollution

After Public Equity returns raw JSON:

- `investment_rating` falls back to `B`.
- `expectation_gap.gap_score` falls back to `50`.
- `expectation_gap.market_believes` falls back to `pending verification`.
- `action.current_action` falls back to `add to watchlist`.
- Presenter can convert fallback values into Chinese display strings.
- Presenter can generate `financial_validation`, `catalysts`, `disconfirming_signals`, and `next_action` if upstream fields are weak.

This can make missing financial work appear as a complete investment judgment.

## Coverage Concerns

Public Equity prompt is broad, but input data is not broad. It lacks:

- sector-specific KPIs
- industry-specific valuation rules
- company financial statements
- peer fundamentals
- price/volume regime beyond simple summaries
- market consensus expectations

The output can look professional for many industries because the LLM knows generic equity-investing language, but true coverage is shallow.

## V3 Implication

In V3, Public Equity should be a research layer only. It should not produce final coaching answers directly.

Recommended source trace examples:

```json
{
  "public_equity.valuation_odds": "missing",
  "public_equity.financial_validation": "llm_pending_verification",
  "public_equity.expectation_gap": "llm",
  "public_equity.investment_rating": "llm_low_confidence"
}
```

If financial or valuation data is absent, V3 should show `missing`, not `B`, `50`, or a polished valuation paragraph.
