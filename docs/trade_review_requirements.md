# AI 复盘报告需求说明

## 背景

AI 复盘报告原先存在两个主要问题：

1. 买卖点信息重复展示，买点/卖点结论和复盘建议反复出现，用户难以聚焦。
2. 报告生成过慢，尤其是 Presenter AI 二次包装和长 memo 生成导致等待时间过长。

此外，Trade Execution 不能只用本地规则判断。买卖点质量需要结合题材、板块强弱、个股短线位置、产业/投资上下文，由大模型解释为什么买点好或不好、卖点是否合理。

## 产品目标

默认报告要更快，同时保留足够清楚的交易复盘结论。

报告生成分为两档：

- 快速报告：WANG / Public Equity 只输出前端需要的结构化 JSON，不输出长 memo。
- 更详细的报告：WANG / Public Equity 输出结构化 JSON，并附加较长 deep_memo。

前端需要提供模式选择：

- 快速报告
- 更详细的报告

## 信息架构要求

### 首屏公司研究

首屏应展示：

- 公司名称、代码、业务/主题
- 产业评级
- 投资评级
- 关键标签
- 一句话结论

如果命中旧 cache，且 cache 中已有 memo 或 market_hype_reason，不应被 `待验证` / `结论待验证` 占位字段覆盖。

### 买卖点复盘

买点和卖点各自一块功能卡即可。

每张卡需要展示：

- 日期
- 成交价
- 判断
- 原因
- 个股涨跌幅
- 沪深300/ETF 涨跌幅
- 板块/概念涨跌幅
- 相对大盘强弱
- 相对板块强弱
- 日内位置

不要重复堆叠多张相同卖点卡，也不要在“下次执行规则”里重复同一句买卖点原因。

### Trade Execution

Trade Execution 必须是两层：

1. 规则层：基于真实行情和成交事实计算。
2. LLM 增强层：结合规则事实和 Workbench 投研上下文，解释买卖点为什么好/不好。

LLM 增强层要回答：

- 买点是否跟随题材
- 买点是否短线结构合理
- 是否只是弱势补涨或板块带动
- 卖点是否卖早
- 卖出时是否确认题材或板块退潮
- 下一次确认信号是什么

## 性能目标

不通过裁剪报告内容来“假加速”，而是通过职责拆分和减少重复 AI 调用来提速。

目标方向：

- Presenter 默认不调用 AI。
- 快速报告默认 JSON-only。
- WANG / Public Equity 并行。
- Trade Execution 与 Workbench 并行。
- 多轮报告小并发构建，顺序保持稳定。
- 盯盘行情并行获取。

## 兼容性要求

- 保持现有前后端 API 兼容。
- 只允许新增可选 debug/timing/metrics 字段。
- 不删除已有 WANG、Public Equity、Trade Execution、OCR、盯盘能力。
- 更详细报告可以更慢，但必须可由前端明确选择。
